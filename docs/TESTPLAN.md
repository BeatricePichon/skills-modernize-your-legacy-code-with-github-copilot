# COBOL Student Account Test Plan

## Scope

This test plan covers the current business logic and visible implementation behavior of the COBOL student account application. It is intended for stakeholder validation of the legacy behavior before or during migration to a Node.js implementation.

## Test Cases

|Test Case ID|Test Case Description|Pre-conditions|Test Steps|Expected Result|Actual Result|Status (Pass/Fail)|Comments|
|---|---|---|---|---|---|---|---|
|TC-001|Verify the application starts and displays the main menu options|The application is compiled and executable|1. Launch the application. 2. Observe the first screen.|The menu is displayed with options for View Balance, Credit Account, Debit Account, and Exit. The prompt asks for a choice from 1 to 4.||| |
|TC-002|Verify the default student account balance can be viewed on first use|The application is running and no prior credit or debit has been performed in the current session|1. Start the application. 2. Enter `1` for View Balance.|The application displays the current balance as the initial default balance of `1000.00` with COBOL numeric formatting. No balance change is made.||| |
|TC-003|Verify a valid credit increases the balance|The application is running with the initial balance or a known current balance|1. Enter `2` for Credit Account. 2. Enter a valid positive amount, for example `100.00`. 3. View the balance.|The application reads the current balance, adds the entered amount, stores the updated balance, and displays the new balance. Example: `1000.00` becomes `1100.00`.||| |
|TC-004|Verify a valid debit decreases the balance when funds are sufficient|The application is running with a known balance greater than the debit amount|1. Enter `3` for Debit Account. 2. Enter a valid amount smaller than the current balance, for example `100.00`. 3. View the balance.|The application reads the current balance, subtracts the debit amount, stores the updated balance, and displays the new balance. Example: `1000.00` becomes `900.00`.||| |
|TC-005|Verify a debit equal to the current balance is allowed|The application is running with a known balance, for example `1000.00`|1. Enter `3` for Debit Account. 2. Enter the full current balance amount. 3. View the balance.|The application allows the transaction because the balance is greater than or equal to the requested debit. The resulting balance becomes zero.||| |
|TC-006|Verify a debit larger than the current balance is rejected|The application is running with a known balance smaller than the requested debit amount|1. Enter `3` for Debit Account. 2. Enter an amount larger than the current balance, for example `1500.00` when the balance is `1000.00`. 3. View the balance.|The application displays `Insufficient funds for this debit.` The balance remains unchanged because no write occurs.||| |
|TC-007|Verify balance changes persist within the same application session|The application is running with the default or another known balance|1. Enter `2` and credit `200.00`. 2. Enter `1` to view the balance. 3. Enter `3` and debit `50.00`. 4. Enter `1` again to view the balance.|The first balance inquiry reflects the credited amount. The second balance inquiry reflects the later debit. Example: `1000.00` to `1200.00`, then to `1150.00`.||| |
|TC-008|Verify the application handles an invalid menu option|The application is running at the main menu|1. Enter a value outside the supported menu choices, for example `9`. 2. Observe the response.|The application displays `Invalid choice, please select 1-4.` and returns to the main menu loop. No account balance change is made.||| |
|TC-009|Verify the application exits when the user selects Exit|The application is running at the main menu|1. Enter `4`. 2. Observe the response.|The application sets the continue flag to stop the loop and displays `Exiting the program. Goodbye!` before terminating.||| |
|TC-010|Verify a balance inquiry does not change the stored balance|The application is running with a known balance|1. View the balance using option `1`. 2. View the balance again without any credit or debit in between.|Both balance inquiries show the same value. A read operation does not alter the stored balance.||| |
|TC-011|Verify crediting zero is accepted by the current implementation|The application is running with a known balance|1. Enter `2` for Credit Account. 2. Enter `0.00`. 3. View the balance.|The application accepts the input, writes the unchanged balance, and displays the same balance. This reflects the current implementation because there is no validation preventing zero amounts.||| |
|TC-012|Verify debiting zero is accepted by the current implementation|The application is running with a known balance|1. Enter `3` for Debit Account. 2. Enter `0.00`. 3. View the balance.|The application accepts the input because the current balance is greater than or equal to zero. The stored balance remains unchanged. This reflects the current implementation because there is no validation preventing zero amounts.||| |
|TC-013|Verify the application manages only one in-memory account balance for the session|The application is running|1. Credit or debit the account. 2. Return to the main menu. 3. View the balance again.|The application continues to operate on a single shared balance value. There is no prompt or behavior for selecting a specific student account.||| |
|TC-014|Verify the balance resets to the default value in a new application run|A prior session has changed the balance and the application has been exited|1. Start the application. 2. Credit or debit the balance. 3. Exit the application. 4. Restart the application. 5. View the balance.|The balance starts again from the default `1000.00` because the current implementation stores the balance only in memory and does not persist it between runs.||| |
|TC-015|Verify sequential operations are applied in order|The application is running with the default balance of `1000.00`|1. Credit `100.00`. 2. Debit `25.00`. 3. Credit `10.00`. 4. View the balance.|The final balance reflects all operations in order. Example: `1000.00` to `1100.00`, then `1075.00`, then `1085.00`.||| |
|TC-016|Verify the user is returned to the menu after each non-exit interaction|The application is running|1. Perform a balance inquiry. 2. Perform a credit or debit. 3. Observe the screen after each action.|After each completed operation, the application returns to the main menu until the user explicitly selects Exit.||| |

## Notes

- This plan reflects the current COBOL behavior, including implementation-driven behavior such as accepting zero-value credits and debits.
- The current application does not support multiple student accounts, student identifiers, or persistent storage between sessions.
- The `Actual Result`, `Status (Pass/Fail)`, and `Comments` columns are intentionally left blank for stakeholder walkthroughs and later test execution.
